# 커리어와 프로젝트 텍스트 관리

## 커리어

`careers.json`의 회사 7개가 `/Career` 화면에 배열 순서대로 표시됩니다.

- `company`: 회사명
- `period.start` / `period.end`: 회사 재직 기간 (`YYYY-MM`). 현재 재직 중인 회사는 `end: null`, `isCurrent: true`로 설정합니다.
- `employmentType`: 고용 형태
- `role`: 담당 업무를 바탕으로 정리한 역할이며 공식 직급이나 직책을 의미하지 않습니다.
- `summary` / `responsibilities`: 회사에서 맡은 업무 요약 / 주요 업무 문장 배열
- `techStack`: 사용 기술 배열. 창헬스케어는 이력서의 해당 회사 프로젝트 기술을 모아 정리했습니다.
- `sourcePages`: 원본 이력서 근거 페이지. 화면에 표시하지 않습니다.

이력서에 명시된 재직 시작·종료 월을 사용하며, 프로젝트 수행 기간과 구분합니다. 이력서의 재직 중 표기를 유지했고 회사 업종·규모 등 원문에 없는 기업 소개는 추가하지 않았습니다.

`/Career` 상단의 총 경력은 `careers.json`에서 계산해 표시합니다. 규칙은 다음과 같습니다.

- 시작 월과 종료 월을 모두 포함해 셉니다. 예를 들어 `2013-07` ~ `2014-10`은 16개월입니다.
- 회사 간 겹치는 달은 한 번만 셉니다. 용산집의 종료월과 홀세일닥터의 시작월이 모두 `2020-03`이라 이 달은 한 번만 반영됩니다.
- `end`가 `null`인 재직 중 회사는 화면을 여는 시점의 달까지 셉니다. 따라서 값은 매달 자동으로 늘어납니다.
- 이력서에 일 단위 날짜가 없어 월 단위로만 계산합니다. 공백기는 합산에서 빠집니다.

## 프로젝트

`projects.json`에서 프로젝트의 문구와 표시 순서를 관리합니다. 배열 순서가 `/Project` 화면의 표시 순서입니다. 회사 필터, 기술 스택, 담당 기능, 성과, 이미지와 링크가 자동 반영됩니다. 내용이 없는 상세 영역과 기간은 표시하지 않습니다.

| 필드                          | 설명                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `id`                          | 프로젝트를 식별하는 고유 영문 ID. 연결 후에는 유지합니다.                       |
| `title` / `company`           | 프로젝트명 / 소속 회사                                                          |
| `period.start` / `period.end` | `YYYY-MM` 형식. `null`은 이력서에 프로젝트 기간이 명시되지 않았다는 의미입니다. |
| `role` / `summary`            | 담당 역할 / 목록에 표시할 짧은 소개                                             |
| `techStack`                   | 기술 이름 배열                                                                  |
| `contributions`               | 담당 기능별 `title`과 상세 문장 배열 `items`                                    |
| `outcomes`                    | 이력서에 명시된 성과. 수치나 효과를 임의로 추가하지 않았습니다.                 |
| `images`                      | 이미지 객체 배열. 아래 예시를 참고합니다.                                       |
| `links`                       | `{ "label": "서비스", "url": "https://..." }` 형태의 링크 배열                  |
| `sourcePages`                 | 원본 이력서의 근거 페이지. 화면 표시용이 아닙니다.                              |

이미지는 `public/images/프로젝트ID/`에 넣고 다음처럼 등록합니다. 첫 이미지를 대표 이미지로 사용할 수 있습니다.

```json
{
  "src": "/images/chc-health-report/overview.webp",
  "alt": "건강검진 리포트 미리보기 화면",
  "caption": "리포트 미리보기"
}
```

## 이력서 변환 기준

- 제공된 `프론트엔드 개발자 김동현의 이력서.pdf`의 프로젝트 8개를 정리했습니다. 연락처와 학력 등 프로젝트에 불필요한 개인정보는 포함하지 않았습니다.
- 명칭 없는 일반 업무인 용산집의 반응형 웹 개발과 이와이드플러스의 웹디자인 유지보수는 프로젝트 항목에서 제외하고 커리어 데이터에 정리했습니다.
- 계란이력관리, 똑똑건강UP, DDP는 회사 재직 기간만 있으므로 프로젝트 기간을 `null`로 두었습니다. 해당 항목의 기술은 이력서의 회사별 기술 스택에서 옮겼으므로 프로젝트별 사용 여부를 확인하면 좋습니다.
- 온뱅크는 프론트엔드 프레임워크가 명시되지 않아 배포 관련 기술만 기재했습니다.
- 원문 줄바꿈으로 분리된 BaseModal, useModal, CMS, STOMP, My DT 등의 표기를 정리했습니다.
- 폴바셋 팝업은 원문에 '1일 1회 노출'과 '세션스토리지로 대체'가 함께 기재되어 있습니다. 세션을 넘어 일 단위 노출을 어떻게 유지했는지 확인되지 않아, 화면에는 노출 제어와 iOS 대응 사실만 표시합니다.
- 포트폴리오 문구는 관련 기능을 묶고 내부 함수명을 줄여 정리했습니다. 온뱅크 단독 개발 범위는 프론트엔드로 명시하고, 폴바셋의 클레임 감소·접근성 향상 같은 포괄적 성과 표현은 구체적인 구현·개선 내용으로 바꿨습니다.
- `null`과 빈 배열은 정보 미기재 상태입니다. 이미지 경로, 서비스 URL, 기여율과 정량 성과는 임의로 생성하지 않았습니다.
